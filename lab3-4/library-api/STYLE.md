# STYLE.md - правила API «Библиотека»

Правила обязательны для всех новых endpoint. Автоматически проверяются тестами
`lab3-4/tests/test_library_contract.py` (пункты, помеченные ✔).

1. **Ресурсы - существительные во множественном числе, kebab-case.** `/books`,
   `/readers/{reader_id}`. Глаголы в URL запрещены; исключение - осознанные
   действия над ресурсом, которые не сводятся к CRUD: `POST /loans/{loan_id}/return`. ✔
2. **Версия - в `servers`, а не в каждом пути.** Базовый URL заканчивается на `/v1`;
   несовместимые изменения выпускаются как `/v2` (см. таблицу в README.md). ✔
3. **JSON и query-параметры - snake_case.** Имя фильтра совпадает с именем поля
   в ответе (`?reader_id=7`), диапазоны - суффиксами `_gte` (>=) и `_lt` (<):
   `?published_year_gte=1900&published_year_lt=2000`. ✔
4. **Request и response - разные схемы.** `CreateXRequest` содержит только поля,
   которые передаёт клиент, `UpdateXRequest` - только изменяемые поля без `required`
   и с `minProperties: 1`. Серверные поля (`id`, `available_copies`, `registered_at`,
   `loaned_at`, `returned_at`, `status`) помечены `readOnly` и в request-схемах
   отсутствуют. Во всех request-схемах `additionalProperties: false` - неизвестное
   поле даёт `422`, а не молча игнорируется. ✔
5. **Коды ответа.** `200` - чтение/изменение/действие, `201` + `Location` - создание,
   `204` без тела - удаление, `400` - запрос не разобран или недопустим query-параметр,
   `401` - нет токена, `404` - ресурса по id нет, `409` - конфликт состояния или
   бизнес-правила, `422` - значения тела не проходят валидацию. Пустой список -
   это `200` с пустым `data`, а не `404`. ✔
6. **Одна схема ошибки.** Все ответы `4xx` используют `ErrorResponse`:
   `{"error": {"code", "message", "details[], "request_id"}}`. `code` - стабильное
   значение из enum `ErrorCode`, клиенты ветвятся по нему, а не по тексту `message`. ✔
7. **Коллекции всегда пагинируются.** Параметры `limit` (default 20, maximum 100)
   и `offset` (default 0); ответ - `{"data": [...], "pagination": {"limit", "offset", "total"}}`.
   Сортировка - `sort=<поле>` / `sort=-<поле>` с перечислением допустимых значений в enum
   и явным `default`. ✔
8. **Idempotency-Key на опасных POST.** Обязателен там, где повтор наносит ущерб
   (создание выдачи). Ключ - UUID, хранится 24 часа, в description операции описаны
   replay, mismatch и конкурентные повторы. На безопасных POST ключ не требуется. ✔
9. **Даты - RFC 3339 в UTC** (`format: date-time`), nullable-поля объявляются
   как `type: [string, "null"]` и описывают, когда бывают `null`.
10. **Документация - часть контракта.** У каждой операции есть `operationId`
    (camelCase), `summary`, `description` и ровно один тег из `Books` / `Readers` / `Loans`;
    общие схемы, параметры и ответы подключаются через `$ref`; бизнес-ошибки `409`/`422`
    сопровождаются examples. Удаляемые поля сначала помечаются `deprecated: true`. ✔
